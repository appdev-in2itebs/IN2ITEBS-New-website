# The two reviews, as questions somebody can answer

**Print this, or paste the relevant half into an email.** Every line is a question with a short
answer. Nothing here needs a developer.

When it comes back filled in, applying it to the site is about twenty minutes of mechanical work.
**The hour that matters is the one spent answering, not the one spent typing it in.**

# A · The capability register — due 10 February 2027

**Who answers:** delivery leads, practice by practice.
**What it feeds:** `content/capability-status.ts`, which drives `/about/where-we-stand/` — the page
that publishes what we _cannot_ do, and the most distinctive thing on the site.

### The four statuses, and what each commits us to

| Status             | Means                                                                                    |
| ------------------ | ---------------------------------------------------------------------------------------- |
| **Delivered**      | In production at a named client, signed off, with a named person here accountable for it |
| **With a partner** | We deliver this alongside a partner, and we name them before you sign                    |
| **Building**       | We are investing and some of it is live. Ask what is running today                       |
| **Ahead of us**    | We do not do this. If you need it, we say so and point you elsewhere                     |

**"Delivered" is the strict one.** A pilot is not delivered. A proof of concept is not delivered.
Having people with the skill is not delivered. If a line cannot survive that test, it is
"Building" — and saying so is the entire point of the page.

### Certificates — the part the site currently cannot see

The site publishes four credentials and records when **none** of them expires. Until these are
filled in, the build says so on every run. Once a date is in, the build warns thirty days before
and **fails the day after** it lapses.

| Credential       | Issued by — exact name of the body | Certificate number | Valid until | Scan on file? |
| ---------------- | ---------------------------------- | ------------------ | ----------- | ------------- |
| CMMI Level 3     |                                    |                    |             | ☐             |
| ISO 9001         |                                    |                    |             | ☐             |
| ISO/IEC 27001    |                                    |                    |             | ☐             |
| SAP Gold Partner | SAP SE                             |                    |             | ☐             |

> **Take these from the certificates themselves, not from memory.** CMMI appraisals are valid three
> years; ISO 9001 and 27001 run three-year cycles with annual surveillance, and a failed
> surveillance can suspend a certificate mid-cycle; SAP Gold Partner renews annually.
>
> **Issuer matters as much as date.** ISO does not issue certificates — an accredited registrar
> does. The house rule is that a credential names the body that granted it, so until the registrar
> is known the markup publishes the name without an issuer rather than guessing.
>
> **No edition years.** The legacy site cited ISO 9001:2008 and ISO/IEC 20000-1:2005 — both
> withdrawn — and "ISO/IEC 27000:2005", which is the vocabulary document and not certifiable at
> all. No edition is published anywhere until the certificate is in hand. Naming a withdrawn
> edition is worse than naming none: it tells an auditor we have not read our own certificate since 2008.

## What happens after this comes back

1. Statuses and figures are applied to `content/capability-status.ts` and `content/site.ts`.
2. Certificate dates and issuers go into `certifications`, which switches the expiry gate on.
3. **Only then** do `capabilityReviewed` and `contentUpdated` move to that day's date.

That order is the whole discipline. **Moving the dates without doing the review is the one failure
this system cannot catch**, and it is the quickest way to turn a site built on checkable claims
into one that merely says it is.

### And name an owner

`capabilityOwner` currently reads "Marketing and Communications" — a function, not a person who has
been told. Put a name against it and both dates in that person's calendar. The likeliest way this
site dies is not a bug; it is a red build in February that somebody resolves by changing one date.
